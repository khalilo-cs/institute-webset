# الفخامة للأقمشة والستائر — متجر متصل بلوحة إدارة وقاعدة بيانات

نموذج Full‑Stack عربي RTL لمتجر أقمشة وستائر، يعمل محليًا ببايثون وSQLite دون إطار عمل أو خدمة خارجية. يتكوّن من واجهة تسوق عامة، تطبيق إدارة على `/admin`، API داخلية، وقاعدة بيانات تنشأ تلقائيًا.

بيانات المعاينة الحالية: **الفخامة للأقمشة والستائر**، شارع المكرونة، مجمع الشرق، حي مشرفة، جدة. رقم الهاتف مأخوذ من صفحة الخرائط التي زوّدني بها المالك؛ حقل واتساب متروك فارغًا إلى أن يُؤكَّد، والمنتجات والأسعار ما زالت أمثلة.

## التشغيل

يتطلب Python 3.10 أو أحدث. من مجلد المشروع:

```bash
python3 app.py
```

افتح واجهة المتجر على `http://localhost:4173/` ولوحة الإدارة على `http://localhost:4173/admin`.

### حساب المدير

- اسم المستخدم: `admin` (أو قيمة `ADMIN_USERNAME`).
- كلمة المرور: لا توجد كلمة مرور ثابتة داخل الشيفرة. عند أول تشغيل بقاعدة بيانات جديدة يُولّد الخادم كلمة مرور عشوائية ويطبعها **مرة واحدة** في الطرفية؛ انسخها ثم غيّرها من **الإعدادات ← أمان لوحة الإدارة**. أو حدّدها بنفسك قبل أول تشغيل: `ADMIN_PASSWORD='…' python3 app.py` (12 خانة على الأقل).
- إذا وُجدت قاعدة بيانات من تشغيل سابق، تغيير متغير البيئة لا يستبدل كلمة مرورها. إن كانت قاعدتك قد أُنشئت بالنسخة الأولى التي كانت تستخدم كلمة مرور المعاينة المعروفة، فغيّرها فورًا قبل أي استضافة عامة.

## ما يعمل في النظام

- **المتجر العام:** أقسام وبحث وفرز ومفضلة وسلة وقيود مخزون وواجهة متجاوبة.
- **المنتجات:** إنشاء وتعديل وإخفاء وحذف، رفع صور JPG/PNG/WebP، وصف بديل للصورة، السعر بالريال، الرمز، المخزون والقسم.
- **الأقسام:** إضافة وتعديل وإخفاء وحذف؛ يظهر القسم النشط تلقائيًا في المتجر ونموذج المنتج.
- **الطلبات:** العميل يرسل طلبه من واجهة المتجر، فيُحفظ في قاعدة البيانات وتظهر بياناته للمدير. يمكن تحديث الحالة، مراجعة العناصر والأسعار، وتصدير CSV. الكميات تُحجز عند الطلب وتُعاد للمخزون عند إلغاء الطلب.
- **الإعدادات:** اسم المتجر، المدينة، الهاتف وواتساب، العنوان ورابط Google Maps، رسوم التوصيل، وصف التوصيل، عنوان ووصف SEO، وعنوان ومقدمة الواجهة.
- **SEO:** عنوان ووصف متغيران، وصف محلي للمتجر، JSON‑LD من نوع `Store`، canonical وOpen Graph وخريطة موقع وrobots عند تفعيل الجاهزية.
- **الأمان الأساسي:** كلمة مرور المدير مخزنة بتجزئة PBKDF2، جلسة إدارية بملف تعريف HttpOnly، رمز CSRF لعمليات الإدارة، وحدّ لمحاولات الدخول.

## قاعدة البيانات والملفات

ينشئ التطبيق `store.db` تلقائيًا ويملأه بأقسام ومنتجات **أمثلة** في أول تشغيل. الجداول الأساسية: `admins`, `settings`, `categories`, `products`, `orders`, `order_items`. الصور الجديدة تحفظ في `uploads/`، والصور الابتدائية في `assets/`.

احتفظ بنسخة احتياطية من `store.db` ومجلد `uploads/` معًا. ملف قاعدة البيانات والرفع غير مضمنين في حزمة المصدر؛ ينشئهما التطبيق عند التشغيل.

## تجهيز نسخة المتجر الحقيقية

1. سجّل الدخول وعدّل اسم المتجر والمدينة وأرقام الاتصال والسياسات ورسوم التوصيل من **الإعدادات**.
2. عدّل أو احذف المنتجات التجريبية، ثم أضف المنتجات والأسعار والمخزون والصور الحقيقية.
3. راجع محتوى الصفحة والخدمات وسياسات الاستبدال والخصوصية والتوصيل، وأضف المعلومات القانونية المطلوبة لنشاطك.
4. اربط نطاقًا خاصًا وHTTPS على استضافة تدعم تشغيل Python وخدمة SQLite/ملفات دائمة. لا تستضف المشروع على خدمة ملفات ثابتة فقط؛ الخادم مطلوب للـ API والطلبات.
5. بعد استكمال المعلومات والتحقق من الموقع، فعّل **«بيانات المتجر حقيقية وجاهزة للنشر والفهرسة في Google»** من الإعدادات. قبل تفعيلها يظل الموقع `noindex` وشريط المعاينة ظاهرًا.
6. أضف النطاق إلى Google Search Console وGoogle Business Profile، وأرسل `/sitemap.xml`، واكتب محتوى حقيقيًا خاصًا بالمدينة والمنتجات.

تحسين SEO يجهّز الموقع للفهرسة لكنه لا يضمن ترتيبًا أو ظهورًا فوريًا. الترتيب يتأثر بالمنافسة والمحتوى والسمعة والروابط وتجربة الاستخدام.

## حدود هذا الإصدار

- لا يوجد تحصيل إلكتروني أو بوابة دفع، ولا مزامنة مع شركة شحن أو ERP، ولا إرسال رسائل SMS/بريد تلقائي. تُسجل الطلبات للمراجعة داخل لوحة الإدارة؛ أضف مزود الدفع والشحن والتنبيهات بعد اختيار الحسابات والبيانات اللازمة.
- يستخدم النموذج SQLite وذاكرة جلسات الخادم؛ مناسب للمعاينة وبداية منخفضة الحركة. قبل إطلاق واسع، استخدم استضافة دائمة مع HTTPS ونسخ احتياطية ومراقبة، وفكّر بقاعدة مُدارة مثل PostgreSQL.
- صور ونصوص وأسعار المنتجات الافتراضية أمثلة تصميمية، وليست مخزون متجر حقيقي.
