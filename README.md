# الفخامة للأقمشة والستائر — متجر متصل بلوحة إدارة وقاعدة بيانات (+ تطبيق Android)

نظام Full‑Stack عربي RTL لمتجر أقمشة وستائر، يعمل ببايثون القياسية وSQLite دون إطار عمل أو خدمة خارجية. **الموقع والتطبيق ولوحة الإدارة يتصلون بخادم واحد وقاعدة بيانات واحدة**:

| المكوّن | المسار | ملاحظات |
|---|---|---|
| متجر العملاء (الموقع) | `/` وصفحات المتجر (انظر «صفحات الموقع») | كتالوج حي، سلة، طلبات؛ صفحات منتجات وأقسام ومن نحن وتواصل وأسئلة؛ PWA |
| لوحة الإدارة | `/admin/` | تسجيل دخول (+ تحقق بخطوتين اختياري)، منتجات وصور وأقسام وطلبات ورسائل وإحصاءات وإعدادات ونسخ احتياطي وسجل نشاط |
| الخادم وقاعدة البيانات | `app.py` + SQLite | واجهة API واحدة يستخدمها الموقع والتطبيق والإدارة |
| **تطبيق Android واحد** للعملاء والمدير | `android/` | يفتح المتجر؛ لوحة الإدارة من «دخول الإدارة» أو اختصار الأيقونة |

بيانات النشاط: **الفخامة للأقمشة والستائر**، شارع المكرونة، مجمع الشرق، حي مشرفة، جدة 23444. الهاتف `+966 57 648 6491` مأخوذ من صفحة الخرائط؛ حقل واتساب فارغ عمدًا إلى أن يُؤكَّد. الكتالوج الحالي: 18 موديل ستائر ويفي من صور المتجر، بسعر «حسب الطلب».

> التطبيق (البناء، التثبيت، ما ينقص للإصدار الإنتاجي): **[ANDROID.md](ANDROID.md)** · قياسات الجودة والمعايير: **[docs/QUALITY.md](docs/QUALITY.md)**.

## التشغيل

يتطلب Python 3.10+ ولا يحتاج أي حزمة خارجية:

```bash
python3 app.py
```

المتجر `http://localhost:4173/` والإدارة `http://localhost:4173/admin/`.

### متغيرات البيئة

| المتغير | الافتراضي | الوظيفة |
|---|---|---|
| `HOST` / `PORT` | `127.0.0.1` / `4173` | عنوان الاستماع (`0.0.0.0` فقط للشبكة المحلية أو داخل حاوية خلف وكيل) |
| `DATA_DIR` | مجلد المشروع | `store.db` و`uploads/` و`backups/` — وجّهه إلى قرص دائم |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | `admin` / *(يُولَّد)* | تُستخدم عند إنشاء قاعدة البيانات لأول مرة فقط |
| `TRUST_PROXY` | غير مفعّل | `1` خلف وكيل HTTPS: كوكي `Secure` وHSTS وحساب الحدود لكل عميل |
| `PUBLIC_BASE_URL` | من ترويسة `Host` | العنوان الرسمي `https://…` لـ canonical وsitemap وروابط المشاركة |
| `ORDER_LIMIT_PER_10MIN` | `10` | حد محاولات الطلب العامة لكل عميل |
| `CONTACT_LIMIT_PER_10MIN` | `5` | حد رسائل نموذج التواصل المقبولة لكل عميل |
| `LOG_FORMAT` | نص | `json` لسجلات منظّمة (ip, path, status, ms, rid) |
| `AUTO_BACKUP` / `BACKUP_KEEP` | — / `14` | `1` نسخة احتياطية تلقائية عند التشغيل ثم كل 24 ساعة، والاحتفاظ بآخر N (تظهر قائمتها في الإعدادات ← «النسخ الاحتياطي») |
| `DIGITAL_ASSET_LINKS_FILE` | — | يقدّم `/.well-known/assetlinks.json` إن اعتُمد TWA لاحقًا |

### حساب المدير
- المستخدم `admin` (أو `ADMIN_USERNAME`). **لا توجد كلمة مرور في الشيفرة**: تُولَّد عشوائيًا عند أول تشغيل وتُطبع مرة واحدة، أو حدّدها بـ `ADMIN_PASSWORD='…'` (12 خانة+). غيّرها من **الإعدادات**.
- **مرحلة التصميم المحلية**: ملف `.env` (خارج Git وخارج صورة Docker؛ انظر `.env.example`) يحمل `ADMIN_USERNAME` و`ADMIN_PASSWORD`، ومعه `ALLOW_WEAK_PASSWORD=1` الذي يسمح بكلمة مرور من 6 خانات **على هذا الجهاز فقط**. يرفض الخادم الإقلاع بهذا الخيار إن كان `HOST` غير محلي أو مع `TRUST_PROXY` أو `PUBLIC_BASE_URL`. الحساب يُنشأ عند إنشاء قاعدة البيانات لأول مرة، فإن غيّرت `.env` بعد ذلك فاحذف `store.db` أو غيّر كلمة المرور من الإعدادات. **قبل ربط السيرفر**: احذف `ALLOW_WEAK_PASSWORD` وغيّر كلمة المرور إلى 12 خانة فأكثر.
- قاعدة قديمة أُنشئت بالنسخة الأولى (بكلمة معاينة معروفة): غيّر كلمة المرور فورًا قبل أي استضافة عامة.
- **التحقق بخطوتين (TOTP)**: الإعدادات ← «التحقق بخطوتين» ← أدخل المفتاح في Google/Microsoft Authenticator وأكّد برمز. بعدها لا تكفي كلمة المرور.
- تغيير كلمة المرور يُنهي جلسات المدير الأخرى.

## إدارة المحتوى (من الموقع ومن التطبيق بعد تسجيل دخول المدير)

الإدارة نفسها في الموقع والتطبيق (`/admin/`):
- **المنتجات:** إضافة/تعديل/إخفاء/حذف، **حتى 12 صورة لكل منتج** (رفع عدة صور دفعة واحدة، إعادة ترتيب، تحديد الرئيسية، حذف). الصور تُصغَّر داخل المتصفح/التطبيق قبل الرفع (1600px + مصغّرة 600px) فلا مشكلة في صور الجوال الكبيرة. الصور غير المستخدمة تُحذف تلقائيًا.
- **الأقسام:** إضافة بصورة اختيارية، تعديل، إخفاء، حذف، **وترتيب بالأسهم**. القسم يظهر للعملاء فقط إن كان فيه منتجات نشطة.
- **أدوات سريعة:** عند دخول المدير يظهر شريط في المتجر (+ إضافة منتج، الأقسام، الطلبات، لوحة الإدارة) وزر «تعديل المنتج» داخل صفحة كل منتج؛ روابط مباشرة مثل `/admin/#products/new`.
- **الطلبات:** الأسعار تُحسب في الخادم، حجز المخزون وإعادته، حالات، تصدير CSV. السعر 0 = «حسب الطلب».
- **لوحة المعلومات:** مخطط الطلبات لآخر 14 يومًا، المخزون المنخفض، سجل نشاط المدير (من فعل ماذا ومتى ومن أين، دون كلمات مرور).
- **الإحصاءات** (`/admin/#analytics`): مشاهدات صفحات المتجر يوميًا لآخر 7 أو 30 أو 90 يومًا، الصفحات والمنتجات الأكثر زيارة، مصادر الزيارات، وعدد الطلبات ورسائل التواصل في آخر 30 يومًا (انظر «الإحصاءات وGoogle» أدناه).

## صفحات الموقع

كل الصفحات تُولَّد في الخادم داخل **قالب المتجر نفسه** (`index.html`: الرأس والتذييل والسلة والنوافذ والسكربتات)، فتعمل السلة والمفضلة والعرض السريع والطلب في كل صفحة، وتقرأ كلها من قاعدة البيانات نفسها التي يقرأ منها التطبيق ولوحة الإدارة. المحتوى يأتي من الإعدادات والكتالوج فقط (لا أرقام أو تقييمات أو ادعاءات مخترعة)، وكل قيمة تُهرَّب قبل العرض.

| المسار | الصفحة |
|---|---|
| `/` | الرئيسية (كما هي؛ الأسئلة الشائعة فيها من المصدر نفسه `pages.FAQ`) |
| `/products` | كل المنتجات بالبحث (`?q=`) والتصفية والترتيب؛ البطاقات مكتوبة في HTML للزاحفين ولمن لا يشغّل JavaScript |
| `/categories` | الأقسام النشطة التي فيها منتجات |
| `/category/<slug>` | صفحة القسم: اسمه ووصفه وصورته ومنتجاته وتنقّل بين الأقسام |
| `/product/<slug>` | صفحة المنتج الحقيقية: معرض الصور، السعر أو «السعر حسب الطلب»، التوفر، الوصف، إضافة للسلة، مشاركة ونسخ الرابط، ملاحظات التوصيل، ومنتجات من القسم نفسه |
| `/about` | من نحن: عنوان ونص من الإعدادات، الخدمات المعروضة، العنوان والخريطة والهاتف (وأوقات العمل إن أُضيفت) |
| `/contact` | بيانات التواصل ونموذج رسالة (يعمل أيضًا دون JavaScript) |
| `/faq` | الأسئلة الشائعة |
| أي مسار غير موجود | صفحة 404 بهوية المتجر مع بحث وروابط (الحالة 404 و`noindex`) |

- المسار بشرطة مائلة في آخره (`/about/`) يُحوَّل 301 إلى المسار الرسمي.
- لكل صفحة عنوان ووصف وcanonical وOpen Graph وJSON‑LD (`BreadcrumbList` لكل صفحة، `CollectionPage`/`ItemList` للمنتجات والأقسام، `AboutPage`، `ContactPage`، `FAQPage`، و`Product` بمسار «الرئيسية ← القسم ← المنتج»).
- واتساب لا يظهر إلا إذا أُدخل رقمه في الإعدادات؛ الهاتف الحالي رابط اتصال `tel:`.

### نموذج التواصل والرسائل
- `POST /api/contact` (عام مثل الطلبات): `{name, phone, email?, message, page?, consent: true, website}` ← `201 {"ok": true}`. أخطاء الإدخال `400` برسالة عربية، والحد 5 رسائل مقبولة لكل عميل كل 10 دقائق (`CONTACT_LIMIT_PER_10MIN`) ثم `429` مع `Retry-After`. الحقل المخفي `website` (honeypot) إن مُلئ يُرد `201` ولا يُحفظ شيء.
- للمدير (جلسة + `X-CSRF-Token` للكتابة): `GET /api/admin/messages?status=all|new|handled` (الأحدث أولًا، حتى 500، مع `counts`)، `PATCH /api/admin/messages/<id>` بـ `{"status":"new"|"handled"}`، `DELETE /api/admin/messages/<id>`؛ والعمليات تُسجَّل في سجل النشاط. لوحة المعلومات تعرض `new_messages`.
- الإعدادات الجديدة: `about_title` و`about_body` و`opening_hours`، ووصف لكل قسم (`description`). التفاصيل في [DATABASE.md](DATABASE.md).

## الإحصاءات وGoogle

### إحصاءات المتجر الذاتية (دائمًا، بلا ملفات تعريف ارتباط)
- يحسب الخادم كل عرض ناجح (200) بطلب `GET` لصفحة عامة: الرئيسية وصفحات المتجر كلها (ومنها صفحات المنتجات) والخصوصية والشروط. **لا يُحسب:** `HEAD`، صفحات 404 والتحويلات، `/admin` و`/api` والملفات الثابتة، طلبات التحميل المسبق (`Sec-Purpose`/`Purpose: prefetch`)، الزواحف ومعاينات الروابط (وكيل مستخدم يحوي `bot|crawl|spider|slurp|facebookexternalhit|whatsapp|preview` أو فارغ)، وزيارات المدير المسجّل دخوله.
- يُخزَّن **مجموع يومي فقط** (بتوقيت السعودية): `page_views(day, path, views)` و`referrers(day, host, views)` بتحديث UPSERT. المسار دون أي استعلام (كلمة البحث لا تُحفظ)، والمصدر اسم الموقع المحيل فقط إن كان موقعًا آخر، أو `direct` حين لا يوجد مصدر؛ التنقل داخل المتجر لا يُحسب مصدرًا، وبعد 200 مصدر مختلف في اليوم تُجمع البقية في `other`. لا يُحفظ عنوان IP ولا وكيل المستخدم ولا أي كوكي، وتُحذف الأرقام الأقدم من 400 يوم عند التشغيل (ومع الصيانة اليومية إن فُعّل `AUTO_BACKUP`).
- للمدير: `GET /api/admin/analytics?days=7|30|90` ← `{daily:[{date,views}], totals:{today,last7,last30}, top_pages:[{path,views}], top_products:[{slug,name,views}], referrers:[{host,views}], orders_last30, contact_last30}`؛ أي فترة أخرى `400`.

### Google Analytics 4 وSearch Console (اختياريان، يملكهما المتجر)
- من الإعدادات ← **«جوجل والتحليلات»**: `ga4_id` (بالشكل `G-XXXXXXXX`) و`google_site_verification` (قيمة `content` من وسم HTML في Search Console، أو الوسم كاملًا فيُستخرج منه). تُرفض القيم غير الصالحة (`400`)، والحقل الفارغ يوقف الخدمة.
- **الملكية:** تُنشأ خاصية Analytics وحساب Search Console من **حساب Google الخاص بالمتجر**، ويُمنح المطوّر صلاحية «محرّر» في Analytics و«مستخدم كامل» في Search Console.
- رمز التحقق يُضاف `<meta name="google-site-verification">` في رأس كل الصفحات العامة.
- **دون `ga4_id` لا يتغير شيء:** CSP نفسها، لا شريط، لا طلبات خارجية.
- **مع `ga4_id`:** تُضاف إلى CSP صفحات المتجر فقط (لا لوحة الإدارة) `script-src https://www.googletagmanager.com` و`connect-src`/`img-src https://*.google-analytics.com https://*.analytics.google.com https://*.googletagmanager.com`. يظهر شريط موافقة عربي (منطقة `role=region` بزرّي «قبول» و«رفض» ورابط سياسة الخصوصية) حتى يختار الزائر؛ يُحفظ الاختيار في `localStorage` بالمفتاح `fakhama-consent-v1`، ويعيد زر «إعدادات ملفات التعريف» في التذييل فتح الشريط. لا يُحمَّل `gtag.js` إلا بعد «قبول»، بعنصر سكربت يحمل nonce الصفحة، مع Consent Mode (الافتراضي مرفوض ثم السماح بالتحليلات فقط) وتعطيل Google Signals وتخصيص الإعلانات. «رفض» لا يحمّل شيئًا؛ وسحب الموافقة لاحقًا يوقف الإرسال فورًا ويحذف ملفات `_ga`. محاولة gtag الاحتياطية إلى `www.google.com/g/collect` (خارج القائمة المسموح بها في CSP) يُجاب عنها محليًا فلا تُرسل ولا تُسجَّل مخالفة CSP.
- تُضاف إلى سياسة الخصوصية فقرة Google Analytics (من يعالج البيانات، ما يُجمع، المدة، طريقة سحب الموافقة) **فقط** عند تعبئة `ga4_id`.

## للعملاء
كتالوج وبحث وفرز ومفضلة وسلة؛ **معرض صور** لكل منتج؛ **صفحة لكل منتج** (`/product/<slug>`) بمعاينة غنية عند المشاركة على واتساب، زر مشاركة ونسخ الرابط؛ نموذج الطلب بموافقة صريحة على سياسة الخصوصية؛ صفحتا **الخصوصية** و**الشروط**؛ عند انقطاع الخادم تظهر رسالة وإعادة محاولة ولا تُعرض بيانات مخترعة.

## المعايير المطبّقة (ملخص — التفاصيل والقياسات في docs/QUALITY.md)
- **الأداء:** Lighthouse 98–100 (جوال وسطح مكتب)؛ ضغط gzip، ETag وطلبات شرطية (304)، تخزين مؤقت للصور، مصغّرات، preload لصورة الواجهة، بلا مكتبات خارجية.
- **إمكانية الوصول (WCAG 2.2 AA):** 0 مخالفات axe على 20 شاشة (جوال/مكتب)؛ رابط تخطٍّ، معالم صفحة، حبس التركيز في النوافذ وإعادته، تباين، أهداف لمس كافية، يحترم تقليل الحركة.
- **SEO:** عنوان/وصف/canonical/hreflang/Open Graph/Twitter يُكتب من الخادم (يقرأه الزاحفون ومعاينات المشاركة)، JSON‑LD (`Store` `WebSite` `Product` `BreadcrumbList` `CollectionPage` `AboutPage` `ContactPage` `FAQPage`)، `sitemap.xml` بالصفحات والأقسام والمنتجات والصور، `robots.txt`. يبقى الموقع `noindex` حتى تفعّل «بيانات المتجر حقيقية وجاهزة للنشر».
- **الأمان:** CSP بـ nonce دون `unsafe-inline` للسكربتات، HSTS، `X-Frame-Options`، COOP/CORP، `Permissions-Policy`؛ PBKDF2؛ جلسات HttpOnly + CSRF؛ TOTP؛ حدود محاولات (مع `Retry-After`)؛ طلبات **idempotent** (`Idempotency-Key`) فلا تتكرر الطلبات عند إعادة الإرسال؛ فحص الصور من المحتوى؛ سجل تدقيق.
- **الخصوصية:** موافقة صريحة وتوقيتها، إحصاءات ذاتية مجمّعة بلا كوكيز ولا بيانات شخصية، Google Analytics اختياري ولا يُحمَّل إلا بموافقة الزائر، لا كوكيز إعلانية، سياسة خصوصية وشروط (قوالب عامة: راجعها مع مختص).
- **التشغيل:** `/api/health` (يفحص القاعدة)، نسخ احتياطي متّسق `python3 app.py backup`، إيقاف سلس عند SIGTERM، سجلات JSON ومعرّف طلب `X-Request-ID`، Dockerfile وCaddy (HTTPS تلقائي)، CI.

## النسخ الاحتياطي والاستعادة
- **من لوحة الإدارة** (الإعدادات ← «النسخ الاحتياطي»، يعمل في الموقع وفي تطبيق Android): زر تنزيل يجلب `GET /api/admin/backup.zip` (للمدير فقط، يُسجَّل في سجل النشاط) باسم `fakhama-backup-<وقت UTC>.zip`، وفيه نسخة متّسقة من `store.db` (بواجهة النسخ الاحتياطي في SQLite، آمنة والخادم يعمل)، ومجلد `uploads/`، و`manifest.json` (إصدار التطبيق، الوقت UTC، عدد صفوف كل جدول، عدد الصور، بصمة SHA-256 لقاعدة البيانات). **احفظ نسخة خارج الخادم أسبوعيًا على الأقل** (مثل Google Drive الخاص بصاحب المتجر)؛ الملف يحوي بيانات العملاء وكلمة مرور المدير المشفّرة فلا تشاركه. تعرض البطاقة أيضًا النسخ الموجودة في `DATA_DIR/backups`.
- **من سطر الأوامر:**
```bash
python3 app.py backup                       # DATA_DIR/backups/store-<وقت>.db و uploads-<وقت>.tar.gz، ويحتفظ بآخر BACKUP_KEEP
python3 app.py export-sql [OUT.sql]         # تفريغ SQL: مخطط كل الجداول وبيانات كل الجداول عدا صفوف admins (بلا OUT: إلى stdout)
python3 app.py restore backup.zip           # استعادة نسخة ZIP — أوقف الخادم أولًا
```
- `export-sql` لا يصدّر صفوف `admins` (تجزئة كلمة المرور ومفتاح التحقق بخطوتين). لاستعماله: `sqlite3 store.db < dump.sql` في مجلد فارغ ثم شغّل الخادم مع `ADMIN_PASSWORD` (12 خانة+) لإنشاء حساب مدير جديد.
- `restore` **يتطلب إيقاف الخادم** (ويرفض إن كان شيء يجيب على `HOST:PORT`؛ `--force` فقط إن كان المنفذ لخدمة أخرى). يتحقق من الأرشيف كاملًا قبل أي تغيير: ZIP سليم (CRC)، أسماء عناصر آمنة فقط (`store.db` و`manifest.json` و`uploads/<اسم>`)، `manifest.json` لهذا المتجر، بصمة قاعدة البيانات وسلامتها (`integrity_check`) وجداولها الأساسية وعدد صفوفها مطابق للبيان، وعدد الصور. عند أي خلل يخرج بالرمز 1 دون تغيير شيء. ثم يحفظ الحالة الحالية في `DATA_DIR/backups/pre-restore-<وقت>.zip`، ويستبدل `store.db` (ويحذف ملفات `-wal`/`-shm` القديمة) ومحتوى `uploads/`. شغّل الخادم بعدها؛ تُرقّى القاعدة تلقائيًا إن كانت من إصدار أقدم.
- النسخ القديمة `store-….db` و`uploads-….tar.gz` تُستعاد يدويًا: أوقف الخادم، انسخ الملف إلى `DATA_DIR/store.db` (واحذف `store.db-wal` و`store.db-shm`) وفكّ أرشيف الصور في `DATA_DIR`.

## تجهيز نسخة المتجر الحقيقية
1. سجّل الدخول وحدّث الإعدادات (الاسم، الهاتف، واتساب إن وُجد، العنوان، رسوم التوصيل).
2. حدّد أسعار الموديلات أو اتركها «حسب الطلب»، وأضف بقية المنتجات والأقسام بصورها.
3. راجع صفحتي الخصوصية والشروط مع مختص قانوني وعدّل ما يلزم لتطبيقاتك الفعلية.
4. استضف على نطاق خاص وHTTPS (انظر النشر)، وغيّر كلمة مرور المدير وفعّل التحقق بخطوتين.
5. فعّل **«بيانات المتجر حقيقية وجاهزة للنشر والفهرسة»**، ثم أضف النطاق إلى Google Search Console (بحساب Google الخاص بالمتجر؛ رمز التحقق من الإعدادات ← «جوجل والتحليلات») وBusiness Profile وأرسل `/sitemap.xml`. Google Analytics 4 اختياري من البطاقة نفسها.
6. نزّل نسخة احتياطية من الإعدادات واحفظها خارج الخادم، وكرّر ذلك أسبوعيًا.
7. لبناء التطبيق الإنتاجي يلزم النطاق الدائم ومفتاح توقيعك: [ANDROID.md](ANDROID.md).

## حدود هذا الإصدار
- لا دفع إلكتروني ولا شحن/ERP ولا رسائل تلقائية، ولا إشعارات دفع للمدير عند وصول طلب أو رسالة تواصل (تظهر في لوحة الإدارة). لم يُفعَّل أي دفع وهمي.
- SQLite وجلسات في الذاكرة (تنتهي عند إعادة التشغيل): مناسب لبداية منخفضة الحركة؛ قبل إطلاق واسع استخدم نسخًا احتياطية خارجية ومراقبة، وفكّر بقاعدة مُدارة.
- المحتوى القانوني قوالب عامة وليس استشارة قانونية. التحقق بخطوتين بإدخال المفتاح يدويًا (بلا رمز QR).
- بعض صور الكتالوج تحمل علامة المتجر النصية (alfakhama) كما في الأصل.
