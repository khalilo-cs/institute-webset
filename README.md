# الفخامة للأقمشة والستائر — متجر متصل بلوحة إدارة وقاعدة بيانات (+ تطبيقا Android)

نظام Full‑Stack عربي RTL لمتجر أقمشة وستائر، يعمل ببايثون القياسية وSQLite دون إطار عمل أو خدمة خارجية. يتكوّن من:

| المكوّن | المسار | ملاحظات |
|---|---|---|
| متجر العملاء | `/` (`index.html`) | كتالوج حي، سلة، طلبات؛ يعمل كـ PWA |
| لوحة الإدارة | `/admin/` (`admin.html`) | تسجيل دخول، منتجات، أقسام، طلبات، إعدادات |
| الخادم وقاعدة البيانات | `app.py` + SQLite | واجهة API واحدة يستخدمها كل شيء |
| تطبيق Android للعملاء | `android/` (flavor `customer`) | يفتح `/` من الخادم نفسه |
| تطبيق Android للإدارة | `android/` (flavor `admin`) | يفتح `/admin/` ويتطلب تسجيل الدخول |

بيانات النشاط الحالية: **الفخامة للأقمشة والستائر**، شارع المكرونة، مجمع الشرق، حي مشرفة، جدة 23444. الهاتف `+966 57 648 6491` مأخوذ من صفحة الخرائط التي زوّد بها المالك؛ حقل واتساب فارغ عمدًا إلى أن يُؤكَّد. الكتالوج الحالي هو صور ستائر الويفي الحقيقية للمتجر (18 موديلًا) بسعر «حسب الطلب»؛ لم تُحدَّد أسعار بعد.

> دليل تطبيقي Android (البناء، التثبيت، ما ينقص للإصدار الإنتاجي): **[ANDROID.md](ANDROID.md)**.

## التشغيل

يتطلب Python 3.10 أو أحدث، ولا يحتاج أي حزمة خارجية:

```bash
python3 app.py
```

افتح المتجر على `http://localhost:4173/` ولوحة الإدارة على `http://localhost:4173/admin/`.

### متغيرات البيئة

| المتغير | الافتراضي | الوظيفة |
|---|---|---|
| `HOST` / `PORT` | `127.0.0.1` / `4173` | عنوان الاستماع. استخدم `HOST=0.0.0.0` فقط لتجربة على الشبكة المحلية أو داخل حاوية خلف وكيل عكسي |
| `DATA_DIR` | مجلد المشروع | مكان `store.db` و`uploads/`. وجّهه إلى قرص دائم في الاستضافة |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | `admin` / *(يُولَّد)* | تُستخدم عند إنشاء قاعدة البيانات لأول مرة فقط |
| `TRUST_PROXY` | غير مفعّل | اضبطه `1` فقط خلف وكيل عكسي HTTPS يضيف `X-Forwarded-For` و`X-Forwarded-Proto`؛ يفعّل وسم `Secure` للكوكي وHSTS ويحسب حدود المحاولات لكل عميل حقيقي |
| `PUBLIC_BASE_URL` | من ترويسة `Host` | العنوان الرسمي (`https://…`) المستخدم في `robots.txt` و`sitemap.xml` |
| `ORDER_LIMIT_PER_10MIN` | `10` | حد محاولات إرسال الطلبات العامة لكل عميل |
| `DIGITAL_ASSET_LINKS_FILE` | — | مسار ملف `assetlinks.json` ليُقدَّم على `/.well-known/assetlinks.json` (لا يلزم لتطبيقات WebView الحالية؛ يلزم فقط إن اعتُمد TWA لاحقًا) |

### حساب المدير

- اسم المستخدم: `admin` (أو قيمة `ADMIN_USERNAME`).
- كلمة المرور: **لا توجد كلمة مرور ثابتة في الشيفرة.** عند أول تشغيل بقاعدة بيانات جديدة يُولّد الخادم كلمة مرور عشوائية ويطبعها **مرة واحدة** في الطرفية؛ انسخها ثم غيّرها من **الإعدادات ← أمان لوحة الإدارة**. أو حدّدها بنفسك قبل أول تشغيل: `ADMIN_PASSWORD='…' python3 app.py` (12 خانة على الأقل).
- إذا وُجدت قاعدة بيانات سابقة فلن تتغير كلمة مرورها بتغيير المتغير. إن كانت قاعدتك قد أُنشئت بالنسخة الأولى (التي كانت تستخدم كلمة مرور معاينة معروفة)، فغيّرها فورًا قبل أي استضافة عامة.
- تغيير كلمة المرور يُنهي جلسات المدير الأخرى على بقية الأجهزة.

## ما يعمل في النظام

- **المتجر العام:** أقسام وبحث وفرز ومفضلة وسلة وقيود مخزون وواجهة متجاوبة. عند تعذّر الوصول إلى الخادم تظهر رسالة وزر «إعادة المحاولة» ويُمنع إرسال الطلب (لا تُعرض منتجات أو أسعار مخترعة).
- **المنتجات:** 18 موديلًا حقيقيًا من كتالوج المتجر جاهزة (السعر حسب الطلب: `price = 0`). إنشاء وتعديل وإخفاء وحذف، رفع صور JPG/PNG/WebP (حتى 5MB، مع فحص نوع الملف من محتواه)، وصف بديل للصورة، السعر بالريال، الرمز، المخزون والقسم.
- **الأقسام:** إضافة وتعديل وإخفاء وحذف؛ يظهر القسم النشط تلقائيًا في المتجر ونموذج المنتج.
- **الطلبات:** العميل يرسل طلبه، فيُحفظ في قاعدة البيانات ويظهر للمدير. تُحسب الأسعار والإجمالي في الخادم لا من المتصفح. تُحجز الكميات عند الطلب وتُعاد عند الإلغاء. تحديث الحالة وتصدير CSV.
- **الإعدادات:** اسم المتجر، المدينة، الهاتف وواتساب، العنوان ورابط الخريطة (روابط http/https فقط)، رسوم التوصيل، SEO، عنوان الواجهة.
- **SEO:** عنوان ووصف، JSON‑LD من نوع `Store`، canonical وOpen Graph. `robots.txt` يمنع الفهرسة و`sitemap.xml` غير متاح حتى تفعّل «بيانات المتجر حقيقية وجاهزة للنشر» من الإعدادات.
- **PWA:** `manifest.webmanifest` للمتجر و`admin-manifest.webmanifest` للإدارة (نطاق `/admin/`) وأيقونات مستقلة، و`sw.js` لا يخزّن أي API أو صفحة إدارة أو طلب أو جلسة، ويكتفي بصفحة «لا يوجد اتصال» وصور الهوية.

## الأمان

- كلمة المرور بتجزئة PBKDF2‑SHA256 (310 آلاف دورة)، جلسة بكوكي `HttpOnly; SameSite=Lax` (+`Secure` خلف HTTPS)، رمز CSRF لكل عملية كتابة، حد 8 محاولات دخول/5 دقائق لكل عميل، وحد لإرسال الطلبات العامة.
- استعلامات SQLite كلها مُعامَلة (parameterized). الواجهة تُهرّب كل نص قبل عرضه.
- ترويسات: `Content-Security-Policy`، `X-Frame-Options: DENY`، `X-Content-Type-Options`، `Referrer-Policy`، `Permissions-Policy`، `X-Robots-Tag: noindex` للإدارة.
- الملفات المقدَّمة محصورة في صفحات معروفة ومجلدات `assets/` و`uploads/` و`icons/`؛ أي مسار آخر (مثل `store.db` أو `app.py`) يعيد 404. (في النسخة الأولى كان `GET /assets/../store.db` يعيد قاعدة البيانات كاملة؛ أُصلح وله اختبار.)
- الصور المرفوعة تُخزَّن بأسماء عشوائية، ولا تُقبل مسارات صور إلا لملفات موجودة داخل `assets/` أو `uploads/`.

## قاعدة البيانات والملفات

ينشئ التطبيق `store.db` تلقائيًا في `DATA_DIR` ويملأه بأقسام ومنتجات **أمثلة** في أول تشغيل (انظر [DATABASE.md](DATABASE.md)). الصور الجديدة في `uploads/` والابتدائية في `assets/`. احتفظ بنسخة احتياطية من `store.db` و`uploads/` معًا. قواعد البيانات القديمة تُرقّى تلقائيًا (مسارات الصور النسبية تُحوَّل إلى مطلقة).

## الاختبارات

```bash
python3 -I -m unittest discover -s tests -v          # 31 اختبارًا للخادم (لا تلمس أي بيانات حقيقية)
NODE_PATH=$(npm root -g) node tests/e2e_ui.cjs       # اختبار واجهة بمتصفح Chromium على شاشة جوال (يتطلب playwright)
cd android && ./gradlew :app:testCustomerDebugUnitTest   # اختبارات وحدة Android
cd android && ./scripts/verify-release-guards.sh        # يتأكد أن بناء الإصدار الإنتاجي يرفض الإعدادات غير الصالحة
```

كل اختبار خادم يشغّل نسخة مستقلة بمجلد بيانات مؤقت وكلمة مرور عشوائية.

## تجهيز نسخة المتجر الحقيقية

1. سجّل الدخول وعدّل اسم المتجر والمدينة وأرقام الاتصال والسياسات ورسوم التوصيل من **الإعدادات**، وأكّد رقم واتساب إن وُجد.
2. حدّد أسعار الموديلات (أو اتركها «حسب الطلب») وأضف بقية المنتجات (رول، شرائح، كهربائية، أقمشة) بصورها الحقيقية؛ الأقسام الفارغة لا تظهر للعملاء.
3. راجع محتوى الصفحة وسياسات الاستبدال والخصوصية والتوصيل، وأضف المعلومات القانونية المطلوبة لنشاطك.
4. استضف على خادم يشغّل Python مع **نطاق خاص وHTTPS** (مثلًا Caddy أو nginx كوكيل عكسي أمام `app.py` مع `TRUST_PROXY=1` و`HOST=127.0.0.1`) ومساحة دائمة لـ `DATA_DIR`. لا تستضفه كملفات ثابتة فقط.
5. غيّر كلمة مرور المدير. ثم فعّل **«بيانات المتجر حقيقية وجاهزة للنشر والفهرسة في Google»**.
6. أضف النطاق إلى Google Search Console وGoogle Business Profile وأرسل `/sitemap.xml`.
7. لبناء تطبيقي Android الإنتاجيين يلزم النطاق الدائم ومفتاح توقيع خاص بالمالك: **[ANDROID.md](ANDROID.md)**.

تحسين SEO يجهّز الموقع للفهرسة لكنه لا يضمن ترتيبًا أو ظهورًا فوريًا.

## حدود هذا الإصدار

- لا يوجد تحصيل إلكتروني ولا بوابة دفع، ولا مزامنة مع شركة شحن أو ERP، ولا رسائل SMS/بريد تلقائية. تُسجَّل الطلبات للمراجعة داخل لوحة الإدارة. لم يُفعَّل أي دفع وهمي.
- لا إشعارات دفع (push) للمدير عند وصول طلب جديد؛ يراجع المدير لوحة الطلبات.
- يستخدم النموذج SQLite وجلسات في ذاكرة الخادم (تنتهي عند إعادة التشغيل)؛ مناسب لبداية منخفضة الحركة. قبل إطلاق واسع استخدم نسخًا احتياطية ومراقبة، وفكّر بقاعدة مُدارة مثل PostgreSQL.
- أسعار الموديلات الحالية غير محددة (حسب الطلب) وكمية المخزون 999 تعني «تفصيل حسب الطلب»؛ عدّلها من لوحة الإدارة.
- بعض صور الكتالوج تحمل علامة المتجر النصية (alfakhama / الفخامه للستائر والاقمشه) لأنها كذلك في الأصل؛ استبدل الصورة من لوحة الإدارة بنسخة بلا علامة إن رغبت.
