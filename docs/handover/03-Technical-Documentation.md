# التوثيق التقني

مرجع تقني لنظام متجر الفخامة للأقمشة والستائر: البنية، والملفات، ونموذج البيانات، ومتغيرات البيئة، ونموذج الأمان، والأداء وإمكانية الوصول وSEO، وتصميم الإحصاءات بما يحفظ الخصوصية، وتطبيق Android، والاختبارات. كل ما هنا مأخوذ من الشيفرة المصدرية في `source-code.zip`؛ التفاصيل الأدق في `README.md` و`DATABASE.md` و`ANDROID.md` و`docs/QUALITY.md` داخلها.

## البنية العامة

النظام **خادم واحد وقاعدة بيانات واحدة** يخدمان الموقع ولوحة الإدارة وتطبيق Android معًا:

```text
                 الإنترنت (HTTPS 443 / HTTP 80 → تحويل إلى HTTPS)
                                  │
                      ┌───────────▼───────────┐
                      │  Caddy 2 (حاوية caddy) │  شهادة Let's Encrypt تلقائية وتجديدها
                      └───────────┬───────────┘
                                  │ reverse_proxy app:4173 (شبكة Docker الداخلية فقط)
                      ┌───────────▼───────────┐
                      │  app.py (حاوية app)    │  Python stdlib: ThreadingHTTPServer
                      │  صفحات + API + ملفات   │  pages.py · seo.py · legal.py · totp.py
                      └───────────┬───────────┘
                                  │
             DATA_DIR=/data (Docker volume: store-data)
             ├── store.db        SQLite (WAL) — قاعدة البيانات الوحيدة
             ├── uploads/        الصور المرفوعة (أسماء عشوائية)
             └── backups/        نسخ يومية تلقائية + نسخ ما قبل الاستعادة

   العملاء:  متصفح الموقع  ·  لوحة الإدارة /admin/  ·  تطبيق Android (WebView) ← كلها إلى الخادم نفسه
```

- **لا توجد قاعدة بيانات داخل التطبيق ولا في المتصفح:** السلة والمفضلة فقط تُحفظ محليًا على جهاز العميل (`localStorage`) حتى يُرسل الطلب.
- **صفحات المتجر تُكتب في الخادم** داخل قالب واحد هو `index.html` (الرأس والتذييل والسلة والنوافذ والسكربت)، ثم يكمّل سكربت الصفحة التفاعل (السلة، المفضلة، العرض السريع، المعرض، النماذج). لذلك تعمل القراءة والبحث ونموذج التواصل حتى دون JavaScript.
- **لوحة الإدارة** صفحة واحدة (`admin.html`) تتعامل مع واجهة `/api/admin/*` بصيغة JSON.

## التقنيات

| الطبقة | التقنية |
|---|---|
| الخادم | Python 3.10+ (المكتبة القياسية فقط: `http.server`، `sqlite3`، `hashlib`، `hmac`، `gzip`، `zipfile`…)، بلا أي حزمة خارجية |

| التكامل المستمر | GitHub Actions (`.github/workflows/ci.yml`): اختبارات الخادم، واختبارات وحدة Android وLint |

## نموذج البيانات

ينشئ `app.py` المخطط تلقائيًا عند أول تشغيل (`init_db`)، ويرقّي القواعد الأقدم في مكانها (إضافة الجداول والأعمدة الجديدة ومفاتيح الإعدادات دون المساس بالقيم الموجودة). المخطط الكامل في `02-Database/schema.sql`.

| الجدول | الحقول الرئيسية | ملاحظات |
|---|---|---|
| `settings` | `key` (مفتاح أساسي)، `value` | بيانات المتجر والواجهة وSEO و`site_ready` وصفحة «من نحن» (`about_title`، `about_body`، `opening_hours`) وGoogle (`ga4_id`، `google_site_verification`)، ومفاتيح داخلية لتنفيذ التهيئة مرة واحدة |
| `admins` | `username`، `password_hash`، `totp_secret`، `updated_at` | PBKDF2-SHA256 بـ 310,000 تكرار وملح عشوائي 16 بايت؛ `totp_secret` فارغ = التحقق بخطوتين غير مفعّل |
| `categories` | `slug` (مفتاح أساسي)، `name`، `sort_order`، `active`، `image`، `description` | خمسة أقسام افتراضية: `curtains`، `roller`، `blinds`، `electric`، `fabrics` |
| `products` | `id`، `name`، `slug` (فريد)، `category` ← `categories.slug`، `description`، `price`، `image`، `alt`، `badge`، `sku`، `stock`، `featured`، `active`، `created_at`، `updated_at` | `price = 0` تعني «السعر حسب الطلب»؛ `image` نسخة من الصورة الرئيسية |
| `product_images` | `product_id` ← `products.id` (حذف متتالٍ)، `path`، `thumb`، `position` | معرض حتى 12 صورة؛ الموضع 0 هو الرئيسية |
| `orders` | `id`، `order_number` (فريد، بالشكل `MH-YYMMDD-NNNNN`)، `customer_name`، `phone`، `city`، `address`، `notes`، `status`، `subtotal`، `delivery_fee`، `total`، `consent_at`، `created_at`، `updated_at` | الحالات: `new`، `confirmed`، `preparing`، `shipped`، `delivered`، `cancelled` |
| `order_items` | `order_id` ← `orders.id` (حذف متتالٍ)، `product_id` ← `products.id` (يصبح NULL عند حذف المنتج)، `product_name`، `sku`، `unit_price`، `quantity` | نسخة من بيانات المنتج وقت الطلب |
| `messages` | `id`، `name`، `phone`، `email`، `message`، `page`، `status` (`new`/`handled`)، `consent_at`، `created_at`، `handled_at` | رسائل نموذج التواصل؛ لا يُحفظ عنوان IP |
| `audit_log` | `at`، `actor`، `action`، `detail`، `ip` | سجل نشاط المدير، آخر 5000 سجل، بلا كلمات مرور أو رموز |
| `page_views` | `(day, path)` مفتاح أساسي، `views` | إحصاءات يومية مجمّعة بتوقيت السعودية |
| `referrers` | `(day, host)` مفتاح أساسي، `views` | المواقع المحيلة يوميًا؛ بعد 200 مصدر مختلف في اليوم تُجمع البقية في `other` |

**سير الطلب والمخزون:** في معاملة واحدة (`BEGIN IMMEDIATE`) يتحقق الخادم من أن كل منتج نشط وأن المخزون كافٍ، ويعيد حساب الأسعار ورسوم التوصيل من قاعدة البيانات (لا من المتصفح)، ثم يحفظ الطلب وبنوده ويخصم الكميات. الإلغاء يعيد الكميات، وإعادة التفعيل تحجزها من جديد إن كفى المخزون.

**بيانات البداية:** 18 منتجًا (`wavy-01` … `wavy-18`) من صور المتجر في قسم `curtains` بسعر 0 ومخزون 999، تُضاف مرة واحدة لكل قاعدة بيانات؛ المنتج المحذوف لا يعود بعد إعادة التشغيل.

## متغيرات البيئة

| المتغير | الافتراضي | الوظيفة |
|---|---|---|
| `HOST` / `PORT` | `127.0.0.1` / `4173` | عنوان الاستماع. داخل Docker: `0.0.0.0` (الحاوية غير منشورة للخارج؛ Caddy فقط) |
| `DATA_DIR` | مجلد الشيفرة | مكان `store.db` و`uploads/` و`backups/`. في Docker: `/data` على وحدة تخزين دائمة |
| `ADMIN_USERNAME` | `admin` | اسم المدير، يُستخدم عند إنشاء قاعدة البيانات أول مرة فقط |
| `ADMIN_PASSWORD` | *(يُولَّد)* | كلمة مرور المدير الأولى (12 خانة فأكثر)، عند إنشاء القاعدة أول مرة فقط؛ إن تُركت فارغة تُولَّد عشوائيًا وتُطبع مرة واحدة |
| `TRUST_PROXY` | غير مفعّل (`1` في Docker) | خلف وكيل HTTPS: يقرأ `X-Forwarded-For`/`X-Forwarded-Proto`، ويفعّل كوكي `Secure` وHSTS |
| `PUBLIC_BASE_URL` | من ترويسة `Host` | العنوان الرسمي `https://…` لروابط canonical وsitemap والمشاركة (في Docker: `https://${DOMAIN}`) |
| `ORDER_LIMIT_PER_10MIN` | `10` | حد محاولات الطلب لكل عنوان IP كل 10 دقائق |
| `CONTACT_LIMIT_PER_10MIN` | `5` | حد رسائل التواصل المقبولة لكل عنوان IP كل 10 دقائق |
| `LOG_FORMAT` | نص (`json` في Docker) | `json` لسجلات منظّمة |
| `AUTO_BACKUP` / `BACKUP_KEEP` | متوقف (`1` في Docker) / `14` | نسخة احتياطية عند التشغيل ثم كل 24 ساعة، والاحتفاظ بآخر N، مع كنس الصور اليتيمة وحذف الإحصاءات الأقدم من 400 يوم |
| `DIGITAL_ASSET_LINKS_FILE` | — | يقدّم `/.well-known/assetlinks.json` إن اعتُمد TWA لاحقًا |
| `ENV_FILE` | `.env` بجانب `app.py` | ملف متغيرات محلي؛ `off` لتعطيله |
| `ALLOW_WEAK_PASSWORD` | — | لمرحلة التصميم على جهاز واحد فقط: يسمح بكلمة مرور من 6 خانات. **يرفض الخادم الإقلاع به** إن كان `HOST` غير محلي أو مع `TRUST_PROXY` أو `PUBLIC_BASE_URL` |
| `DOMAIN` (لـ `docker compose`) | — (إلزامي) | نطاق المتجر لـ Caddy و`PUBLIC_BASE_URL` |

## أوامر التشغيل والصيانة

```bash
python3 app.py                               # تشغيل الخادم: المتجر / ولوحة الإدارة /admin/
python3 app.py backup                        # نسخة متّسقة: backups/store-<UTC>.db و uploads-<UTC>.tar.gz (يحتفظ بآخر BACKUP_KEEP)
python3 app.py export-sql [OUT.sql]          # تفريغ SQL لكل الجداول عدا صفوف admins
python3 app.py restore backup.zip [--force]  # استعادة نسخة ZIP من لوحة الإدارة (أوقف الخادم أولًا)
```

- **`restore`** يرفض العمل إن كان شيء يجيب على `HOST:PORT`، ويتحقق من الأرشيف كاملًا قبل أي تغيير: سلامة ZIP، أسماء العناصر الآمنة فقط، `manifest.json` الخاص بهذا المتجر، بصمة SHA-256 لقاعدة البيانات، `integrity_check`، الجداول الأساسية، وعدد صفوف كل جدول وعدد الصور. ثم يحفظ الحالة الحالية في `backups/pre-restore-<UTC>.zip` ويستبدل `store.db` ومحتوى `uploads/`. عند أي خلل يخرج بالرمز 1 دون تغيير شيء.
- **`/api/health`** يفحص الاتصال بقاعدة البيانات ويُستخدم في `HEALTHCHECK` الخاص بـ Docker.
- **الإيقاف السلس:** عند `SIGTERM` (`docker stop` أو systemd) يُكمل الخادم الطلبات الجارية ثم يخرج.

## نموذج الأمان

| المجال | التنفيذ |
|---|---|
| كلمات المرور | PBKDF2-HMAC-SHA256 (310,000 تكرار، ملح 16 بايت)، مقارنة ثابتة الزمن؛ لا توجد كلمة مرور في الشيفرة؛ 12 خانة حدًا أدنى |
| الجلسات | رمز عشوائي (`secrets.token_urlsafe(36)`) في كوكي `fakhama_admin` بخصائص `HttpOnly` و`SameSite=Lax` و`Secure` خلف HTTPS؛ صلاحية 12 ساعة؛ محفوظة في الذاكرة؛ تغيير كلمة المرور يُنهي الجلسات الأخرى |
| CSRF | كل عملية كتابة إدارية تتطلب ترويسة `X-CSRF-Token` مطابقة لرمز الجلسة؛ نموذج التواصل العام يرفض الطلبات القادمة من مواقع أخرى (`Origin`/`Sec-Fetch-Site`) |
| التحقق بخطوتين | TOTP (RFC 6238: SHA-1، 6 أرقام، 30 ثانية، سماحية خطوة واحدة) |
| حدود المحاولات | الدخول: 8 إخفاقات/5 دقائق لكل IP؛ الطلبات: 10/10 دقائق؛ التواصل: 5/10 دقائق؛ الرد `429` مع `Retry-After` |
| الحقن | كل استعلامات SQL بمعاملات (`?`)؛ كل قيمة في HTML تُهرَّب؛ JSON-LD يُهرَّب فيه `<` |
| رؤوس الأمان | CSP بـ nonce لكل استجابة دون `unsafe-inline` للسكربتات والأنماط، `X-Frame-Options: DENY`، `frame-ancestors 'none'`، `X-Content-Type-Options`، `Referrer-Policy`، `Permissions-Policy`، COOP/CORP، HSTS خلف HTTPS |
| الصور | JPG/PNG/WebP فقط، فحص التوقيع الفعلي للملف، 5 MB حدًا أقصى، أسماء عشوائية، تقديم من `uploads/` فقط مع منع الخروج من المجلد |
| السجلات | سجل وصول (JSON) بلا أجسام الطلبات أو بيانات الدخول، ومعرّف طلب `X-Request-ID`، وسجل تدقيق لعمليات المدير |

التفاصيل بندًا بندًا مع الدليل من الشيفرة وما يلزم على الخادم في **قائمة التحقق الأمني** (`06-Accounts/Security-Checklist.pdf`).

## محركات البحث (SEO)

- لكل صفحة عنوان ووصف وcanonical وhreflang وOpen Graph وTwitter Card تُكتب في الخادم، فتقرؤها الزواحف ومعاينات واتساب دون JavaScript.
- بيانات منظمة JSON-LD: `Store`/`LocalBusiness` و`WebSite` في الرئيسية، و`BreadcrumbList` لكل صفحة، و`CollectionPage`/`ItemList` للمنتجات والأقسام، و`AboutPage` و`ContactPage` و`FAQPage`. عنصر `Product` (مع `Offer`) يُنشر للمنتجات ذات السعر فقط؛ منتجات «السعر حسب الطلب» تأخذ `BreadcrumbList` وحده لأن Google لا يقبل منتجًا بلا عرض سعر.
- `sitemap.xml` بالرئيسية وصفحات المتجر والقانونية والأقسام والمنتجات مع صورها، و`robots.txt` يمنع `/admin` و`/api/`.
- **بوابة الجاهزية:** حتى تفعيل `site_ready` تكون كل الصفحات `noindex` ويمنع `robots.txt` كل شيء وتعطي `sitemap.xml` الرمز 404.
- المسار بشرطة مائلة في آخره (`/about/`) يُحوَّل `301` إلى المسار الرسمي؛ صفحة 404 بهوية المتجر وحالة 404 و`noindex`؛ نتائج البحث (`?q=`) والقسم الفارغ `noindex`.

## الإحصاءات وتصميم الخصوصية

**إحصاءات ذاتية بلا ملفات تعريف ارتباط (دائمًا):**

- يُحسب كل عرض ناجح (200) بطلب `GET` لصفحة عامة. لا يُحسب: `HEAD`، صفحات 404 والتحويلات، `/admin` و`/api` والملفات الثابتة، التحميل المسبق (`Sec-Purpose`/`Purpose: prefetch`)، الزواحف ومعاينات الروابط (وكيل مستخدم يحوي `bot|crawl|spider|slurp|facebookexternalhit|whatsapp|preview` أو فارغ)، وزيارات المدير.
- يُخزَّن **مجموع يومي فقط** بتوقيت السعودية: المسار دون استعلام (كلمة البحث لا تُحفظ)، واسم الموقع المحيل فقط إن كان موقعًا آخر أو `direct`. **لا عنوان IP ولا وكيل مستخدم ولا كوكي ولا معرّف**، وتُحذف الصفوف الأقدم من 400 يوم.

**Google Analytics 4 (اختياري، ملك المتجر):**

- دون `ga4_id` لا يتغير شيء: CSP نفسها، لا شريط، لا أي طلب خارجي.
- مع `ga4_id`: تتسع CSP **لصفحات المتجر فقط** (لا لوحة الإدارة) لنطاقات Google الموثقة، ويظهر شريط موافقة عربي. لا يُحمَّل `gtag.js` إلا بعد «قبول»، مع Consent Mode (الافتراضي رفض كل شيء ثم السماح بالتحليلات فقط) وتعطيل Google Signals وتخصيص الإعلانات. «رفض» لا يحمّل شيئًا، وسحب الموافقة يوقف الإرسال ويحذف ملفات `_ga`. يُحفظ الاختيار في `localStorage` بالمفتاح `fakhama-consent-v1`.
- فقرة Google Analytics في سياسة الخصوصية تُضاف تلقائيًا فقط عند تعبئة `ga4_id`.

**الخصوصية عمومًا:** موافقة صريحة مع وقتها في الطلبات والرسائل، تقليل البيانات، لا كوكيز إعلانية، سياسة خصوصية وشروط (قوالب عامة تحتاج مراجعة قانونية وفق نظام حماية البيانات الشخصية السعودي).

## تطبيق الويب (PWA)

`sw.js` محدود عمدًا: لا يخزّن `/api/` ولا صفحات الإدارة ولا `/uploads/` ولا أي طلب غير `GET`؛ التنقل يأتي من الشبكة أولًا ولا يُخزَّن إلا صفحة `offline.html` كبديل، فلا يرى العميل أسعارًا أو كميات قديمة. يُخزَّن مؤقتًا فقط ما في `/assets` و`/icons`.

## تطبيق Android

| البند | القيمة |
|---|---|
| المعرّف | `com.alfakhamah.store` (لا يتغير بعد النشر على Google Play) |
| الاسم | «الفخامة» |
| الإصدار | `versionName 1.0.1`، `versionCode 2` |
| الحد الأدنى | Android 7.0 (`minSdk 24`)، `targetSdk 36` |
| البنية | `MainActivity` (WebView)، `NavigationPolicy` (ما يبقى داخل التطبيق وما يُفتح خارجه)، `ServerOrigin` (عنوان الخادم) |

- **عنوان الخادم مدمج وقت البناء** في النسخة الإنتاجية (`SERVER_ORIGIN`) ولا يمكن تغييره من الجهاز؛ HTTPS فقط وثقة بشهادات النظام فقط.
- **حارس الإصدار الإنتاجي** في `android/app/build.gradle.kts`: يرفض البناء إن لم يكن `SERVER_ORIGIN` نطاقًا دائمًا بـ `https://` (يرفض `http://` و`localhost` وعناوين IP والنطاقات المؤقتة والوهمية والنطاق بلا نقطة) أو إن غابت بيانات التوقيع. يختبره `android/scripts/verify-release-guards.sh`.
- **الأمان:** صلاحية واحدة (`INTERNET`)، `allowBackup=false`، شهادة غير صالحة تقطع الاتصال، المحتوى المختلط ممنوع، روابط `intent:` و`javascript:` و`data:` و`blob:` ممنوعة، التنزيل مسموح من `/api/admin/` فقط، ومنع لقطات الشاشة (`FLAG_SECURE`) أثناء عرض لوحة الإدارة.
- **ما اختُبر:** 13 اختبار وحدة، وLint بلا أخطاء، والتثبيت على محاكي Android 14. **لم تُجرَّب تدفقات عرض الصفحات داخل التطبيق على هاتف حقيقي** (المحاكي البرمجي دون تسريع عتادي)، فجرّبه على هاتف قبل النشر.
- **البناء:** `android/scripts/build-test-apks.sh` (تجريبي) و`android/scripts/build-release.sh` (إنتاجي، بمفتاح العميل). التفاصيل في دليل النشر و`ANDROID.md`.

## السجلات والمراقبة

- سجل الوصول: نص افتراضيًا، أو JSON مع `LOG_FORMAT=json` بالحقول `ts` و`ip` و`method` و`path` (دون الاستعلام) و`status` و`ms` و`rid`. لا تُكتب أجسام الطلبات أو كلمات المرور.
- كل استجابة تحمل `X-Request-ID` لربط شكوى المستخدم بسطر السجل.
- أخطاء الخادم غير المتوقعة تُطبع كاملة في سجل الخادم فقط، ويتلقى العميل رسالة عامة «حدث خطأ غير متوقع في الخادم.».
- `GET /api/health` للمراقبة الخارجية (مثل خدمة Uptime مجانية).

## الاختبارات

```bash
python3 -I -m unittest discover -s tests -v                          # اختبارات الخادم (أكثر من 90 اختبارًا)
NODE_PATH=$(npm root -g) node tests/e2e_ui.cjs                       # متصفح Chromium على شاشة جوال (Playwright)
NODE_PATH=$(npm root -g):/path/node_modules node tests/a11y_axe.cjs  # إمكانية الوصول (يتطلب npm i axe-core)
cd android && ./gradlew :app:testDebugUnitTest                       # اختبارات وحدة Android
cd android && ./scripts/verify-release-guards.sh                     # حارس الإصدار الإنتاجي
```

- **اختبارات الخادم** تغطي الأمان (CSP، الجلسات، CSRF، حدود المحاولات، الصور، المسارات)، وSEO، والصفحات، والطلبات والمخزون، والرسائل، والإحصاءات، وإعدادات Google، والتحقق بخطوتين بمتجهات RFC 6238 الرسمية، والنسخ الاحتياطي والتصدير والاستعادة، وترقية القواعد القديمة. كلها تعمل ببيانات مؤقتة.
- **اختبار المتصفح** يشغّل خادمًا مؤقتًا ويجرّب طلبًا كاملًا، ورفع الصور، والمعرض، وشريط المدير، والأقسام، والتحقق بخطوتين، وانقطاع الخادم، وكل الصفحات الجديدة.
- تعمل اختبارات الخادم وAndroid تلقائيًا في GitHub Actions مع كل دفع (push) وطلب دمج.

## حدود معروفة في هذا الإصدار

- لا دفع إلكتروني، ولا إشعارات بريد أو جوال للمدير عند وصول طلب أو رسالة.
- حساب مدير واحد؛ لا توجد واجهة لإضافة مستخدمين أو أدوار.
- الجلسات في ذاكرة الخادم: إعادة التشغيل تُخرج المدير.
- لا يمكن تعديل مبلغ طلب أو حذفه من اللوحة.
- رابط صفحة المنتج يُعاد بناؤه من الاسم عند الحفظ من نافذة التعديل (انظر دليل لوحة الإدارة).
- التحقق بخطوتين دون رمز QR ودون رموز استرداد.
- SQLite على خادم واحد: مناسب لحركة منخفضة إلى متوسطة؛ قبل توسع كبير تُراجع الاستضافة وقاعدة البيانات.
- ملفات Docker لم تُشغَّل في بيئة التطوير (لا يوجد فيها خادم Docker يعمل)؛ تُختبر على الخادم الفعلي عند أول نشر.
- النصوص القانونية قوالب عامة وليست استشارة قانونية.
